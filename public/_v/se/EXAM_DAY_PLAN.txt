PROBLEM STATEMENT -> DIAGRAM (10-second method)
  Problem ma:   Nouns (Student, Course, Payment)       -> Class diagram classes / ER entities / DFD data stores
                Persons + external systems             -> Use case actors / DFD external entities / swimlanes
                Verbs (enroll, pay, approve)           -> Use cases / Activity actions / Methods / Messages / DFD processes
                "if / else / retry"                    -> Activity decision diamond / sequence alt frame
                "one-to-many, many-to-many"            -> ER + class multiplicity (1, 0..*, 1..*)
  Example (Library): Actors = Member, Librarian | Use cases = Search Book, Issue Book, Return Book, Pay Fine, Manage Books
                     Classes = Member, Book, Issue, Fine | ER: Member 1:N Issue, Book 1:N Issue.
  Aa folder ma Library nu UML pan che (extra example): Extra_Library_UML_Example.pdf

PRACTICAL PRAMANE KAI KARVU
  1  SDLC           : 7 phases + activities + output table, model (Agile/Waterfall) ane karan, benefits, conclusion.
  2  SRS            : cheatsheet na headings (Introduction, Overall Description, Specific Requirements) - 8-10 FR, 5-6 NFR.
  3  Use case       : actors + use cases + boundary + include/extend. Niche 1-2 line ma problem ane actor-usecase table lakho.
  4  Activity/Swim  : flow order ma lakho, decision [yes]/[no]; swim lane = actor-wise columns.
  5  Class          : classes (3 compartments), + / - visibility, multiplicity, inheritance, composition.
  6  Sequence       : objects upar, messages order ma, return dashed, alt frame.
  7  DFD            : Level 0 (1 process) -> Level 1 (3-5 processes + D1, D2 stores), balanced.
  8  ER             : entities, PK underline, relationships, cardinality table.
  9  Complexity     : function ni CFG, V(G) = E - N + 2 = P + 1, test per path, coverage %.
  10 Test suite     : EP + BVA + Decision table + Error guessing table; code ma chalavo.
  11 Login/OAuth    : test groups ma 8-10 test cases; code ma chalavo.
  12 Blisk          : 4 devices, check table, bugs list.
  13 Bug report     : template (cheatsheet) - 3-5 bugs.

VIVA ma POOCHE TO
  SDLC = software banavvani step-by-step process | SRS = requirements no document | Use case = actor ane system no vyavhar |
  Class diagram = static structure | Sequence = time order ma messages | DFD = data nu flow (control nahi) |
  ER = database design | V(G) = independent paths = ochha ma ochha test cases |
  Black box = andar no code jovo nahi (EP, BVA) | White box = code jovo (statement/branch/path coverage) |
  Severity = bug ketlo serious | Priority = kyare fix karvo | Regression testing = fix pachi junu badhu pharithi test.
